## What this batch does, and why each part is reversible

- **`0043`** adds `meal_periods`, and **explicitly drops** the 8-argument
  `save_meal` before creating the 9-argument one. That drop matters: leaving
  both overloads makes `save_meal(unknown × 7)` ambiguous, which is a real
  failure I hit on a local stack during development. Reverting means restoring
  the 8-arg definition recorded below and dropping the 9-arg one.
- **`0044`** adds nullable columns to `app_users`, `institutions` and
  `classes`, adds new functions and triggers, and **reissues eleven existing
  authorization helpers** with one added condition each. The previous body of
  every one of them is recorded below — that is what makes it reversible
  without a data dump.
- **`0045`** replaces `save_meal` again (revision-on-content-change only).
- **`0046`** adds one trigger on `app_users`.

**Nothing in this batch drops a column, drops a table, or deletes a row.**

This is a schema record, not a data dump, and is not a substitute for one.
Supabase's managed backup / PITR state for this project was not verified here.

CREATE OR REPLACE FUNCTION public.app_current_role()
 RETURNS app_role
 LANGUAGE sql
 STABLE SECURITY DEFINER
 SET search_path TO 'public'
AS $function$
  select role from app_users where user_id = auth.uid();
$function$;

 RETURNS uuid

   where user_id = auth.uid() and role in ('school_admin', 'classroom_staff');

 RETURNS boolean
 LANGUAGE sql
 STABLE SECURITY DEFINER

          where s.class_id = c.id and sp.user_id = auth.uid()

$function$;

CREATE OR REPLACE FUNCTION public.app_can_see_user(p_user uuid)
 RETURNS boolean
 LANGUAGE sql
 STABLE SECURITY DEFINER
 SET search_path TO 'public'
AS $function$

    select 1 from app_users me
    where me.user_id = auth.uid()
      and (
        me.user_id = p_user
        or me.role = 'super_admin'
        or (me.role = 'school_admin'
            and me.institution_id = (select institution_id from app_users target where target.user_id = p_user))

                join students s on s.id = sp.student_id
                join app_users target on target.user_id = sp.user_id
               where sp.user_id = p_user
                 and target.role = 'parent'
                 and s.institution_id = me.institution_id

      )

## `save_meal` as it stood before `0043`

The 8-argument form. `0043` drops it by exact signature and `0045` replaces the
9-argument successor.

```sql
CREATE OR REPLACE FUNCTION public.save_meal(p_meal_id uuid, p_name text, p_ingredients jsonb, p_allergens jsonb, p_nutrition jsonb, p_portion text, p_image_path text, p_nutrition_status text DEFAULT 'NOT_APPROVED'::text)
 RETURNS uuid
 LANGUAGE plpgsql
 SECURITY DEFINER
 SET search_path TO 'public'
AS $function$
declare v_meal uuid; v_next int;
begin
  if not app_is_super_admin() then
    raise exception 'Only a Super Admin may manage the Meal Library';
  end if;
  if coalesce(btrim(p_name),'') = '' then
    raise exception 'Meal name is required';
  end if;

  if p_meal_id is null then
    insert into meals (name, active, created_by) values (p_name, true, auth.uid())
      returning id into v_meal;
    v_next := 1;
  else
    v_meal := p_meal_id;
    update meals set name = p_name, updated_at = now() where id = v_meal;
    if not found then raise exception 'Meal % not found', p_meal_id; end if;
    select coalesce(max(revision_no),0) + 1 into v_next from meal_revisions where meal_id = v_meal;
  end if;

  insert into meal_revisions (meal_id, revision_no, name, ingredients, allergens,
                              nutrition, portion, image_path, nutrition_status, created_by)
  values (v_meal, v_next, p_name,
          coalesce(p_ingredients,'[]'::jsonb), coalesce(p_allergens,'[]'::jsonb),
          coalesce(p_nutrition,'{}'::jsonb), p_portion, p_image_path,
          coalesce(p_nutrition_status,'NOT_APPROVED'), auth.uid());

  update meals m set current_revision_id =
    (select id from meal_revisions where meal_id = v_meal and revision_no = v_next)
   where m.id = v_meal;

  return v_meal;
end $function$;
```
